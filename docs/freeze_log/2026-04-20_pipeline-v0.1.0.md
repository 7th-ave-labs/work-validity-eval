### O*NET scope

- O*NET 30.2 database (pinned URL path `db_30_2_text` in
  `scripts/download_onet_core.sh`).
- Job zones kept: **3, 4, 5** (inclusive). Zone 3 inclusion rule: we include
  the full zone-3 set in the reference sample; Zone 3 rows that do not
  involve document-heavy, analytical, or technical record work get low
  `salience_weight` automatically because their importance × relevance ×
  Core-multiplier is small; Zone-3 rows with high salience (e.g. health
  technicians, regulatory clerks) contribute proportionally.
- Task type retained: all types (Core + Supplemental). Core tasks receive a
  1.0 weight; Supplemental a 0.5 weight in `salience_weight`.

### Clustering family (primary + stability)

- **Primary:** HDBSCAN, `min_cluster_size=40`, `min_samples=10`, metric
  "euclidean" on L2-normalized embeddings (cosine-proxy).
- **Stability check:** KMeans with `k=30`, seed 42. Agreement on non-noise
  tasks: ARI ≈ 0.48, NMI ≈ 0.78 (see `data/derived/cluster_stability.json`).
- The clusters are used only as a proposal / sampling frame for the frozen
  taxonomy in `data/work_pattern_labels.csv`.

### Work-pattern labels (frozen)

- 28 labels, ids + definitions in `data/work_pattern_labels.csv`.
- Each label carries a `minimum_task_contract` (one sentence) and a set of
  `inclusion_examples` + `exclusion_examples`. These are the conservative
  inference rules used in Steps 2 and 5 of the plan.
- Labels were drafted via stratified LLM proposal
  (`scripts/propose_work_patterns.py`, default `gpt-5.4-mini`, temperature 0.2) and
  then hand-consolidated in `scripts/finalize_work_patterns.py`.

### Embeddings

- Model id: `text-embedding-3-small`.
- Input template: `"{occupation_title}: {task_text_clean}"` (aligned with
  the clustering template noted in `docs/task_analysis_plan.md`).
- No seed control is needed for the embedding model; the API version is
  captured in `notebooks/reproduce.ipynb`.

### Coding

- Task coding: default chat model `gpt-5.4-mini` (override with env `CODING_MODEL`
  or script flags); temperature 0.0, JSON-mode responses, batch size 20, 20 parallel
  workers. Pin a model snapshot in this log if you need bit-for-bit replication.
- Allowed explicit-requirement tokens (closed vocabulary): `comparison_to_standard`,
  `calculation`, `specified_source`, `update_required`,
  `communication_required`, `documentation_required`, `regulatory_form`,
  `multi_party_interaction`, `physical_action`, `multi_step_procedure`,
  `quality_check`.
- Output: `data/derived/onet_tasks_coded.parquet` (12,611 rows).
- Recoded on 2026-04-20 via `scripts/rerun_after_chat_model_change.sh` after
  switching the default chat model to `gpt-5.4-mini`. Previous coded parquet
  retained as `data/derived/onet_tasks_coded.parquet.bak_20260420_214313` (not
  checked in; regenerate via the rerun script). Pin an exact provider snapshot
  id here if a future result feeds the paper.

### When the main claims would weaken

- Mapped benchmark scored units **usually satisfy** the minimum task contract in a blind or stratified audit.
- Headline gaps **flip** under alternate defensible weightings without that sensitivity being reported.
- Frozen labels **collapse** to uninformative agreement with an independent bucketing in a pre-specified diagnostic check.

### Known scope caveats (same as plan)

- ONET task text ≠ full job performance.
- Claims about "what evaluations cover" apply to this specific 10-source
  sample, not to all evaluations.
- Clusters are exploratory; the frozen taxonomy is what the comparison rests
  on.
